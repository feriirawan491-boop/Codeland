## Boundaries and controls

`/partner` provides an account login gate and organization registration. A real registration creates a draft requiring documents, agreement acceptance and platform review. The explicit **Activate partner demo workspace** action seeds approved local examples, Nusa Hospitality and Jelajah Mobility, for exploration. Owner/Operations/Finance persona switching is an explicitly authorized demo role player for the demo owner, not a production authentication feature. Invited real account members only receive their own membership and assigned listings.

The context snapshot includes organization, membership and version; changing identity/organization clears private component state and stale responses are ignored. Writes go through typed adapters with permission, object scope, version and state checks. Mutation command IDs support result reconciliation. Read scenarios: `?scenario=loading|empty|error|timeout|unauthorized|forbidden|rate_limited`; calendar/decision/CRM/support adapter mutations support unknown-result fixtures. Rate-limit retry honors a three-second demo delay.

Public projection stores only public listing/resource IDs, sale eligibility and calendar/rate fields. Hotel/Home new quotes use partner rates and minimum-stay rules; Home buffers are captured for new reservations. Car rate/stop-sell/capacity/buffer are checked alongside the original physical allocation logic. Venue calendar availability is shared at resource level; final venue prices remain explicit structured quotes and never change an existing accepted quote. Published master edits become review drafts; existing transaction snapshots remain unchanged. New custom draft listings need Phase 10 approval and catalog integration before public publication.

Demo file metadata is session-local; file bytes are memory-only. PDF/JPEG/PNG signatures, size up to 5 MB each, and up to three files per upload are validated. Switching accounts clears attachment bytes. File access independently rechecks organization and assignment. Sensitive documents, account numbers and contact data are excluded from URLs and public inventory projection.

## Production integration handoff

All organization authorization and state transitions here are local adapters for frontend validation. A production server must enforce identity, tenant/listing scope, session revocation, concurrency, inventory transactions, immutable finance facts, secure file persistence/scanning and audit retention. Phase 10 owns platform verification, listing publication and real Finance approval. Real payment/refund/payout integrations, document verification, email delivery and notification transport are not implemented by this frontend phase.

No flights orders, channel manager, housekeeping, co-host payout split, fleet API or advertising scope is introduced.

## QA

Unit coverage targets all PTR acceptance risks: Owner/Operations bank permissions, listing completeness and review, inventory conflicts/versions, concurrent Car decisions, organization-scoped customers, service/no-show eligibility, quote drafts and supersession, source reviews and assignment revocation, financial adjustments/payout snapshots, private tickets/files, logout and sales closure. Browser tests exercise role/org switching, listing validation, calendar preview/apply, source reservations, CRM versions, CSV export, support, team revocation, responsive 320/360/768/1024/1440 layouts, English and axe accessibility. Regression covers the connected customer booking and inquiry modules.
